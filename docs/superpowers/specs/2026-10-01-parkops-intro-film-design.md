## 2. 案例事实

来源：部署在 10.3.13.76 的服务器（版本 2.7.22），2026-10-01 用 Justin 的会话只读查询 `/api/admin/status`、`/api/admin/notifications`、`/api/admin/agents/:id/detail`。时间为新加坡时间（UTC+8）。

**车队**
- 监控站点 193 个（查询时在线 184、警告 6、严重 3、离线 0）。
- 告警历史从 2026-09-30 19:39 开始，到 2026-10-01 17:59 共 209 条。
- 从站点上报到系统亮起告警的耗时：中位 16.5 秒，90% 在 24.9 秒以内。

**CK36（运营方 SJS，PMS 电脑 CK36_PMS）**

站点地图上的设备：入口站 CK36E、出口站 CK36X，摄像头 ENTRY、EXIT、BOOTH、TOPUP，以及 NVR。

| 时间 | 事件 | 告警 id |
|---|---|---|
| 11:03:08 | 站点上报：CK36E、CK36X、ENTRY 摄像头、EXIT 摄像头同时失联 | 287–290 |
| 11:03:31 | 系统亮起这 4 条告警（上报后 23 秒） | |
| 11:59:07 | PMS 电脑停止上报，判定离线 | 291 |
| 12:01:31 | PMS 电脑恢复上线 | |
| 12:02:20 | 7 个业务程序被标记为未运行，属于重启后尚未拉起 | 292–298 |
| 12:02:31 | 4 个失联设备全部恢复 | |
| 12:04:31 | 最后一个程序恢复，全部正常 | |

这期间该站点没有远程命令记录，恢复是现场处理的。

**措辞边界**
- 数据能证明"23 秒内标记"，证明不了"比现场来电更早"。画面不出现后一种说法。
- "11:59 现场重启"是根据 PMS 电脑离线约 2 分钟推断的，画面写成 "PMS PC restarted on site"。如果 Justin 知道实际原因，以他说的为准。
- 不显示任何 IP 地址，只显示站点代码和设备名称。

## 3. 分镜

120 BPM，每小节 2 秒，切换点落在拍子上。

| 时间 | 画面 | 屏幕文字 |
|---|---|---|
| 0–6 s | 193 个圆点排成车队网格，全部绿色，按拍脉动 | 193 car park stations. / All running right now. |
| 6–10 s | 其中一个圆点闪了一下 | Something will break. / Who knows first? |
| 10–14 s | 品牌亮相，Watson 打招呼 | ParkOps Watch Dog |
| 14–19 s | 重绘的 CK36 站点地图：中间 PMS 电脑，左右各一条车道，下方 BOOTH、TOPUP、NVR；数据包沿虚线流动 | CK36 · 1 Oct · 11:03:08 |
| 19–25 s | 入口、出口车道的 4 个设备同时变红，数据包停住 | Both lanes lost. |
| 25–31 s | 计数器走到 23 秒；告警铃徽标弹出，4 条真实告警依次落下；Watson 担心 | Flagged in 23 seconds. |
| 31–37 s | 镜头推近红色节点，依次标出站点、车道、设备 | Which site. Which lane. Which device. |
| 37–45 s | 时间轴 11:03 → 11:59 → 12:01 → 12:04，节点逐个变绿；Watson 开心 | All clear at 12:04. |
| 45–52 s | 回到车队网格，告警在不同圆点上亮起又熄灭 | Every station. Every problem. / Flagged in ~16 s, typically. |
| 52–60 s | 结束画面，Watson 摇尾巴 | Know first. / ParkOps Watch Dog |

4 条告警的标题用真实文字：`CK36E Station unreachable`、`CK36X Station unreachable`、`CK36 ENTRY Camera unreachable`、`CK36 EXIT Camera unreachable`。

## 4. 视觉

- **配色**取自 dashboard 的 CSS 变量：
  - 底色 `#0b0f17`，面板 `#0e1320`，边框 `#243049`
  - 文字 `#e5e7eb`，次要文字 `#9ca3af`
  - 正常 `#34d399`，故障 `#f87171`
  - 品牌靛蓝 `#4f46e5` 和 `#818cf8`
- **字体**和界面一致，用系统字体（macOS 上为 SF Pro）。每屏最多 8 个词、两种字号。
- **站点地图**用代码重绘，布局照搬真实页面；设备图标用 ParkOps 仓库的 `dev-*.png`。
- **Watson** 用仓库的精灵图（`mascot-*.webp` 和 `mascot.json`，24 fps，12 列）：
  - 打招呼用 `welcome`，担心用 `worried`，开心用 `happy`，摇尾巴用 `tail`
  - 帧号为 `floor(t × 24)`，保证是时间的纯函数
- **转场**用几何方式，不用淡入淡出，相邻两处不重复：
  - 推移
  - 从红色节点展开的圆形
  - 斜切
- **规格**：1920×1080，60 fps，每帧 8 个子帧做运动模糊。

## 5. 声音

由影片导出的事件表合成，音色全部在中高音区，遵守此前的反馈：落点按含义区分音色，不用低沉的簧片音和闷击。

| 段落 | 编排 |
|---|---|
| 开场车队 | 明亮的大调和弦，木琴跟着圆点 |
| 故障发生 | 抽掉鼓，转小调，只留跟着计数器走的滴答声 |
| 告警落下 | 每条告警一次钢片琴两音下行，共 4 次 |
| 逐个恢复 | 每个节点变绿一声金属片琴，律动逐步回来 |
| 结尾 | 回到大调主和弦 |

响度标准化到 -14 LUFS / -1.5 dBTP。

## 6. 制作

**位置**：Video 仓库，`films/2026-10-parkops-intro/`

| 文件 | 内容 |
|---|---|
| `film.src.html` | 影片源码：`window.DURATION`、`async window.seek(t)` 和 `window.EVENTS` |
| `case.json` | 第 2 节的事实快照，影片只从这里读数据，渲染时不访问服务器 |
| `assets/` | 设备图标和 Watson 精灵图，从 ParkOps 仓库复制 |

**流水线改动**，改在共用脚本里，两部片子都受益：

1. **画布状态串帧**：每帧开始时重置画布并铺底色，转场设置的画笔状态不会带到下一帧。
2. **确定性检查**：`render.mjs --check`
   - 反向那一遍用新开的页面
   - 抽查时刻加上每个转场点前后
   - 比较 PNG 而不是 JPEG
3. **临时目录**：每种模式用自己的工作目录，检查模式不再删除正在渲染的帧。
4. **配乐编排**：`score.py` 的和弦表、鼓的段落和低音型改为从事件表的 `arrangement` 字段读取；缺省时用现有编排，9 月月报不受影响。
5. **响度**：第二遍 loudnorm 若没有走线性模式就警告，并把混音电平压到能走线性的范围。

## 7. 质量检查

1. 每一拍一帧的联系表，先给 Justin 看，确认后再全量渲染。
2. `render.mjs --check` 确定性检查通过。
3. `qa_pops.py` 单帧跳变为 0。
4. 抽取转场和运动中的成片帧，检查运动模糊和文字重叠。
5. 对照第 2 节，逐条核对屏幕上的每个数字和时间。
